# Power BI build guide

Step-by-step instructions to assemble the 5-page dashboard from the exported star schema.
Allow about 2-3 hours. Numbers to check against are in [`data_dictionary.md`](data_dictionary.md)
(section *Check totals*), generated by the export, so nothing here is typed in by hand.

---

## 0. Before you start

**Power BI Desktop runs on Windows only.** On a Mac, use one of:

* a Windows PC or laptop;
* a Windows virtual machine: Parallels Desktop or VMware Fusion (Apple silicon runs Windows 11
  on ARM, which supports Power BI Desktop), or the free UTM;
* a cloud Windows desktop (e.g. Azure Virtual Desktop, Windows 365) if you have access.

Then:

1. Install **Power BI Desktop** (free) from the Microsoft Store or microsoft.com/power-bi.
2. Get the data files. They are not in git (H&M licence: no redistribution). Either
   * on the machine that ran the pipeline: `FDDA_MODE=full make export`, then copy the folder
     `data/processed/powerbi/` (about 105 MB) to the Windows machine; or
   * on the Windows machine itself: clone the repo, `make setup && make data`, then
     `FDDA_MODE=full make analysis forecast tag export`.
3. Copy `dashboard/theme.json` and `dashboard/measures.dax` to the same machine.

---

## 1. Load the tables

1. Open Power BI Desktop > **Blank report**.
2. **Home > Get data > More... > search "Parquet" > Connect.**
3. Paste the full path of one file, e.g. `C:\fdda\powerbi\fact_sales.parquet` > **OK**.
4. In the preview, click **Transform Data** (not Load) the first time, so you can check types.
5. Repeat steps 2-3 for every file (Power Query adds each as a new query):
   `dim_date`, `dim_article`, `dim_product_group`, `dim_channel`, `dim_discount_band`,
   `dim_customer_segment`, `fact_sales`, `fact_kpi_monthly`, `fact_customer`,
   `fact_cohort_retention`, `fact_forecast`, `fact_forecast_metrics`, `fact_discount_bands`,
   `fact_discount_thresholds`.
6. In Power Query, check the column types (icon left of each column name):
   * every `date_key` and `last_purchase_date_key`: **Whole number**;
   * `dim_date[date]`, `month_start`, `week_start`: **Date**;
   * `is_*`, `churned_*`, `in_sales_data`: **True/False**;
   * ids (`article_id`, `product_code`): **Text** (keeps leading zeros);
   * shares, indexes, revenue: **Decimal number**.
7. **Home > Close & Apply.** Loading `fact_sales` (millions of rows) takes a minute.

## 2. Build the model

### 2.1 Mark the date table

Select `dim_date` in the Data pane > **Table tools > Mark as date table** > date column
`date` > **OK**.

### 2.2 Relationships

Open **Model view** (left bar, third icon). Delete any relationships Power BI guessed, then
drag column onto column (or **Home > Manage relationships > New**) to create these. All are
**many-to-one (\*:1), single cross-filter direction**, from the fact (many) to the dimension (one):

| From (many) | To (one) |
|---|---|
| `fact_sales[date_key]` | `dim_date[date_key]` |
| `fact_sales[article_id]` | `dim_article[article_id]` |
| `fact_sales[channel_id]` | `dim_channel[channel_id]` |
| `fact_sales[discount_band]` | `dim_discount_band[discount_band]` |
| `dim_article[product_group_name]` | `dim_product_group[product_group_name]` |
| `fact_kpi_monthly[date_key]` | `dim_date[date_key]` |
| `fact_customer[segment]` | `dim_customer_segment[segment]` |
| `fact_forecast[date_key]` | `dim_date[date_key]` |
| `fact_forecast[category]` | `dim_product_group[product_group_name]` |
| `fact_discount_bands[band]` | `dim_discount_band[discount_band]` |

`fact_cohort_retention` and `fact_forecast_metrics` stay unconnected (measures read them directly).

### 2.3 Helper tables

**Modeling > New table**, then paste each definition from section 0 of `measures.dax`:
`Margin Scenario`, `Churn Window`, `Forecast Model`, `dim_discount_category`.
Then add two more relationships (many-to-one, single direction):

| From (many) | To (one) |
|---|---|
| `fact_discount_bands[category]` | `dim_discount_category[category]` |
| `fact_discount_thresholds[category]` | `dim_discount_category[category]` |

Leave `Margin Scenario`, `Churn Window` and `Forecast Model` unconnected: they only feed slicers.

### 2.4 Measures

1. **Home > Enter data** > name the table `_Measures` > **Load** (an empty table to hold measures).
2. Select `_Measures`, then for each measure in sections 1-5 of `measures.dax`:
   **Modeling > New measure** > paste the block (name line included) > Enter.
3. Set formats (select the measure > **Measure tools**):
   * **Percentage, 1 decimal:** `Avg Discount %`, `Discounted Revenue Share`,
     `Discounted Unit Share`, `Category Revenue Share`, `Revenue MoM %`, `Revenue YoY %`,
     `Orders MoM %`, `AOV MoM %`, `Customer Share`, `Customer Revenue Share`, `Churn Rate`,
     `Cohort Retention`, `Win-back Offer`, `WAPE (backtest)`, `MAPE (backtest)`,
     `WAPE Seasonal Naive`, `MAPE Seasonal Naive`.
   * **Decimal, 2 places:** the `... Index` measures and `Full Price Reference`.
   * **Whole number with thousands separator:** `Revenue (indexed)`, `Units`, `Orders`,
     `Active Customers`, `Customers`, `Revenue at Stake`, forecast unit measures.
4. Right-click `_Measures` > **Hide** the one placeholder column so the table shows the
   calculator icon.

### 2.5 Sort orders and hidden columns

* `dim_discount_band[discount_band]`: **Column tools > Sort by column > band_order**.
* `dim_customer_segment[segment]`: sort by `segment_order`.
* `dim_date[month_name]`: sort by `month_num`.
* Hide key columns from report view (right-click > Hide in report view): every `date_key`,
  `channel_id`, `customer_key`, `last_purchase_date_key`.

### 2.6 Theme

**View > Themes > Browse for themes** > `theme.json`. Colours are a colour-blind-safe order;
keep the defaults rather than recolouring single visuals.

## 3. Build the pages

Rename pages by double-clicking their tab. Canvas: 16:9. Add a text box title on each page
and a small footnote: *"Revenue is indexed (H&M prices are normalised). Source: H&M
Personalized Fashion Recommendations (Kaggle), non-commercial use."*

### Page 1 - Executive KPIs

1. **Slicers (top row):** `dim_date[year]` (tile style), `dim_date[year_month]` (dropdown),
   `dim_channel[channel_name]` (tile).
2. **Cards (one row):** `Revenue (indexed)`, `Units`, `Orders (total)`, `AOV (total)`,
   `Discounted Revenue Share`, `Avg Discount %`.
3. **Line chart: monthly revenue.** X-axis `dim_date[month_start]` (right-click > *Date
   hierarchy* off), Y-axis `Revenue (indexed)`. Tooltips: `Revenue MoM %`, `Revenue YoY %`.
4. **Clustered column chart: orders and AOV by month.** X-axis `dim_date[year_month]`,
   Y-axis `Orders`. Make a second, separate column chart for `AOV` (do not put two measures of
   different scale on two y-axes).
5. **Filter on both monthly visuals:** add `Is Partial Month` to the visual's filters,
   *is 0*, so the first and last (partial) months are excluded.
6. **Line chart: discounted revenue share by month.** X `dim_date[month_start]`, Y
   `Discounted Revenue Share`.

### Page 2 - Category and style performance

1. **Slicers:** `dim_date[year_month]` (between/range), `dim_channel[channel_name]`.
2. **Bar chart:** Y `dim_product_group[product_group_name]`, X `Revenue (indexed)`; tooltip
   `Category Revenue Share`. Sort descending by revenue.
3. **Matrix:** rows `dim_product_group[product_group_name]` > `dim_article[product_type_name]`
   (expandable), values `Revenue (indexed)`, `Units`, `Category Revenue Share`,
   `Avg Discount %`, `Avg Price per Unit`.
4. **Table: top 20 articles.** Columns `dim_article[prod_name]`,
   `dim_article[product_type_name]`, `dim_article[colour_group_name]`, `Revenue (indexed)`,
   `Units`, `Discounted Unit Share`. In the visual's filters, `dim_article[prod_name]` >
   **Top N** > Top 20 by `Revenue (indexed)`.
5. **Table: top 20 styles.** Same, using `dim_article[product_code]` plus `prod_name` (Top N
   20 on `product_code`).

### Page 3 - Discount analysis (threshold marked)

1. **Slicers:** `dim_discount_category[category]` (dropdown, single select, default *All*),
   `Margin Scenario[margin]` (tile, single select, default 0.6, format as %),
   `fact_discount_bands[baseline]` (tile, single select, default *local*).
2. **Card:** `Ceiling Label`. Second card: `Best Band vs Full Price` with the title
   *"Best band vs full price"*.
3. **Line chart: payback curve.** X-axis `dim_discount_band[discount_band]` (sorted by
   `band_order`), Y-axis `Margin Index (selected)` and `Revenue Index`. Add
   `Full Price Reference` as a third line, formatted dashed and grey (*Format > Lines >
   Series*). Turn on data labels for the margin line only.
4. **Column chart: unit uplift.** X `dim_discount_band[discount_band]`, Y `Units Index`.
   **Format > Columns > fx (conditional formatting) > Rules** on `Is Ceiling Band`: 1 = dark
   blue, 0 = light grey, so the ceiling band stands out.
5. **Stacked column chart: revenue by discount band over time** (from actual sales). X
   `dim_date[month_start]`, Y `Revenue (indexed)`, Legend `dim_discount_band[discount_band]`.
6. **Text box (caveat):** *"Associations corrected for article, week and lifecycle effects,
   not a controlled experiment; margins are assumptions (no cost data). See
   reports/pricing_recommendation.md."*

### Page 4 - Customer segments and cohorts

1. **Slicers:** `Churn Window[days]` (tile, single select, default 120),
   `dim_customer_segment[segment]`.
2. **Cards:** `Customers`, `Churn Rate`, `Revenue at Stake` (with a visual filter
   `dim_customer_segment[is_winback_segment]` = True, title *"Revenue at stake, win-back
   segments"*), `Avg Recency (days)`.
3. **Clustered bar chart:** Y `dim_customer_segment[segment]` (sorted by `segment_order`),
   X `Customer Share` and `Customer Revenue Share`.
4. **Table: win-back playbook.** Filter `is_winback_segment` = True. Columns `segment`,
   `customers`, `churned_share`, `revenue_at_stake`, `favourite_categories`,
   `responds_to_band`, `offer_discount`, `action`, `channel`, `timing`, `kpi`.
   Turn on *word wrap* (Format > Values).
5. **Matrix: cohort retention heatmap.** Rows `fact_cohort_retention[cohort]`, columns
   `fact_cohort_retention[months_since]`, values `Cohort Retention`. Visual filter
   `months_since` between 1 and 12. **Format > Cell elements > Background color > fx >
   Gradient**, lowest = light blue, highest = dark blue (one hue, light to dark).

### Page 5 - Forecast vs actual

1. **Slicers:** `dim_product_group[product_group_name]` (dropdown, single select; visual
   filter `is_forecast_category` = True), `Forecast Model[model_label]` (tile, single select).
2. **Line chart: weekly units.** X `dim_date[week_start]`, Y `Actual Units`,
   `Forecast Units`, `Forecast Lower`, `Forecast Upper`. Format the lower and upper lines thin
   and light (same colour as the forecast, 30% transparency), actual in dark grey. Filter
   `dim_date[week_start]` to the last 60 weeks plus the forecast period.
3. **Cards:** `WAPE (backtest)`, `WAPE Seasonal Naive`, `MAPE (backtest)`,
   `MAPE Seasonal Naive`, `Beats Baseline`.
4. **Matrix: accuracy by horizon.** Rows `fact_forecast_metrics[bucket]`, columns
   `fact_forecast_metrics[model]`, values *Max of* `wape` (format %). Visual filter on
   `fact_forecast_metrics[category]` = *All categories* (or the selected category).
5. **Text box:** *"Backtest: 4 rolling 12-week folds; the test window includes the 2020 store
   closures. A model is only useful where it beats the seasonal-naive baseline."*

## 4. Check, export, screenshot

1. **Check totals:** remove all slicer selections; page 1 cards and page 4 `Customers` must
   match the *Check totals* table in `data_dictionary.md`. If they don't, a relationship or a
   column type is wrong (most often `date_key` loaded as text).
2. **Save** as `fdda_dashboard.pbix` *outside the repo* (or in `dashboard/`; `*.pbix` is
   git-ignored because the file embeds the data).
3. **Export PDF:** **File > Export > Export to PDF** > save as `dashboard/dashboard.pdf`.
4. **Screenshots:** for each page, *File > Export > PowerPoint* or Windows *Snipping Tool*
   (Win + Shift + S), saved as PNG in `dashboard/screenshots/`:
   `1_executive.png`, `2_category.png`, `3_discount.png`, `4_segments.png`, `5_forecast.png`.
5. Commit the PDF and screenshots (not the `.pbix`).

## Troubleshooting

| Symptom | Fix |
|---|---|
| Measures show blank on month visuals | `dim_date` not marked as date table, or `fact_kpi_monthly[date_key]` relationship missing |
| Orders / Active Customers card is blank | They need one month selected (distinct counts are not additive); use `Orders (total)` for cards |
| Discount page indexes blank | Select exactly one category and one baseline in the slicers |
| Forecast lines blank | Select one forecast category (`is_forecast_category` = True) and one model |
| `article_id` lost leading zeros | Change its type to Text in Power Query and reload |
| Loading is slow | Normal for `fact_sales`; Power BI compresses it after load |
